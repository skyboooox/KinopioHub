## 在线实例共享一个变量

变量由 `namespace + scope + name` 标识。不同 SDK 使用相同名称，并接入实际互通的 NATS 拓扑，才能交换同一个变量。namespace 用于区分数据名称，不是权限边界；鉴权和 subject 权限由 NATS 配置。

每个 Hub 从空内存和新的 writer 身份开始，向在线副本查询当前记录，并继续接收更新。没有副本时，有界查询结束后得到本地“无值”状态，应用可以直接赋新值。

| 情况 | 结果 |
| --- | --- |
| `set()` 或删除 | 更新本地内存，断网时也可以操作 |
| 重新连接 | 将保留的当前记录与在线副本合并 |
| 新设备加入 | 如果存在在线副本，取得其当前值 |
| 页面重载、进程重启、最后一个副本退出 | 不从本地恢复；只有仍在线的副本可以提供原值 |
| `flush()` 成功 | NATS 传输完成，不代表其他 SDK 已收到或设备已执行 |

记录包含逻辑 counter 和 writer ID。counter 大的版本胜出，相同时按 writer ID 排序，不用设备时间判断新旧。同一版本去重，但再次写入相同值仍产生新版本。删除在内存中保留带版本的标记，阻止旧副本恢复已删除的值。周期查询用于修复遗漏更新。

JSON null、零和 false 都是有效值，未知和不存在由元数据区分。值必须符合接收方 SDK 的容量限制；整数值，包括整数形式的浮点数，不能超出 ±(2^53−1)。不提供历史、落盘、跨变量事务或条件更新。只有 broker 在线，不会为后来加入的 SDK 保留变量。

## 自动局域网节点

创建 Node.js、Python 或 C++ Hub 默认启用发现与选举；仅导入包不会启动节点。成员比较可达性、延迟、失败率和主机负载，通过最短任期和连续改善检查限制频繁切换。胜出者托管普通 NATS Core 进程，其他成员使用其接入点。

选举域由 group、鉴权和 leaf 上游配置决定，namespace 不会创建独立节点。同一进程复用管理器，每个物理主机贡献一票。当前面向小型 IPv4 局域网，每个管理器最多跟踪 32 个其他候选，通过组播发现和直接控制探测协调。防火墙或组播隔离可能阻止协调。

可相互通信的成员最终收敛为一个节点。分区可以各自选举，恢复后允许短暂重叠。SDK 只停止自己启动的进程。托管节点的局域网监听使用明文 NATS/WS，适用于可信局域网；SDK 不安装证书或修改防火墙。

首次胜出时可能下载固定版本、校验完整性的 NATS 执行文件。缓存只保存执行文件，不保存变量。可以通过 `mesh.binary` 指定兼容的现有执行文件。`mesh: false` 使用纯客户端模式。浏览器和 ESP32 不托管节点、不投票。

## 现有服务器与跨网络通信

`servers` 配置客户端入口。SDK 可以探测备选入口，网络质量持续改善时自动切换，并限制抖动。选择入口不会自动连接原本独立的 NATS 系统。

`mesh.upstreams` 为托管节点指定真正的 **leaf-node 入口**。客户端端口不能直接当作 leaf 端口。备选地址应属于同一个上游系统，并使用兼容的传输模式。TCP 探测成功不代表 leaf 已鉴权；SDK 确认真实 leaf 连通后，才应用这个连接上游的本地节点。最小拓扑见 [Server 指南](server.zh.md)。

| 运行环境 | 客户端直连 | 自动节点 |
| --- | --- | --- |
| Node.js / Python | TCP、TLS、WS、WSS | 支持 |
| 浏览器 | WS、WSS | 不支持 |
| C++ | TCP、TLS | 支持；WS/WSS leaf 上游由 NATS Server 连接 |
| ESP32 | TCP、TLS | 不支持 |
| ROS 2 | TCP、TLS | 继承 Python 默认行为；显式 servers 默认纯客户端 |

## SDK 状态与反向控制

SDK 通常每五秒报告身份、运行时间、连接、计数和错误，不包含业务变量或凭据。实例的 `online` / `offline` 表示近期收到报告 / 报告过期；`unknown` 表示观察者自身断连。这不等于设备电源或业务健康检查。报告也只保存在内存。

用变量表达期望状态，用单独的报告值表达设备处理结果。[Python live 通道](python.zh.md#live-通道)和 [ROS 控制](ros.zh.md#反向控制)提供有有效期、不重放的命令。传输确认仍不代表执行器完成动作。
